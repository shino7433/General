# クラウドワークス案件獲得プレイブック

[freelance.md](freelance.md)の主戦場であるクラウドワークス(CW)に特化した、具体的な獲得手順。

**前提となる数字**: クラウドソーシングの提案成約率は**10%前後が目安**(50提案で5件程度)([出典](https://tenkoblog.com/cloudworks/))。つまり案件獲得は確率のゲームであり、「1通入魂」ではなく**打席数×提案の質**の両方で設計する。

## 1. Day 0: アカウント整備(受注の前提条件)

提案文より先にここを済ませる。クライアントは提案を見た後、必ずプロフィールを見に来る。

- [ ] **本人確認を完了する**(プロフィール充実度+10%。同条件なら確認済みが選ばれる([解説](https://atsoho.com/blog/crowdworks-identity-verification-guide-2026)))
- [ ] **CWとのNDA(秘密保持契約)を締結する**(本人確認が前提。NDAオプション付き案件に応募可能になり信頼度も上がる([公式FAQ](https://crowdworks.my.salesforce-sites.com/faq/articles/FAQ/10428?l=ja&url=10428)))
- [ ] プロフィール充実度を100%にする(スキル登録・稼働可能時間・自己紹介)
- [ ] 自己紹介文は[freelance.md §3](freelance.md)の方針で作成: 発注者の言葉(「毎日の手作業をなくします」)で書き、対応時間帯と返信目安を明記
- [ ] ポートフォリオ欄にマイクロツール第1号とサンプルGAS 2本(スクショ/デモ動画付き)を登録
- [ ] 職種は「システム開発・運用」系で登録し、スキルに GAS / Google Apps Script / スプレッドシート / Excel VBA を設定

## 2. 案件の探し方

### 検索キーワードセット(ブックマーク推奨)

毎回この順で検索する:

| 優先 | キーワード | 狙い |
|---|---|---|
| 1 | `GAS` / `Google Apps Script` | 本命。指名スキルなので競合はエンジニアのみ |
| 2 | `スプレッドシート 自動化` / `スプレッドシート 自動` | 非エンジニア発注者が多く要件が小さい |
| 3 | `Googleフォーム 自動` / `フォーム 集計` | 定型パターン([ideas.md B](ideas.md)) |
| 4 | `Gmail 自動送信` / `カレンダー 自動` | 同上 |
| 5 | `Excel マクロ VBA` | GASで代替提案できることがある(「Excelでも動きますがスプレッドシートなら無料で自動実行できます」) |

### 絞り込み条件

- 形式: **プロジェクト形式(固定報酬)** のみ。時間単価制・コンペは避ける。タスク形式は実績稼ぎには使えるが単価が低すぎるので原則使わない
- 予算: 5,000円以上(予算未記載は提案時にこちらから見積り提示)
- 並び順: **新着順**(重要。下記参照)

### 狙い目シグナル(応募判断)

[freelance.md §4](freelance.md)のチェックリストに加えて、CW特有の判断材料:

- **提案数が5件未満** → 競合が少ないうちに出す。掲載から24時間以内の新着が理想
- **募集文が具体的**(「AシートのデータをBに毎朝転記したい」)→ 要件確定が速く、実稼働2〜4時間で収まる
- 発注者の**過去の発注履歴・評価**がある(発注慣れしていて検収がスムーズ)
- 「継続あり」「長期歓迎」の記載 → リピートの入口
- 逆に、提案数30件超の案件・大手SES風の常駐案件はスルー(時間の無駄)

### 新着の拾い方

- 検索条件を保存し、**新着メール通知をON**にする(CWの機能)
- 提案は新着掲載から**24時間以内**に出す。発注者は最初の数通で決めることが多く、早さ自体が差別化になる

## 3. 週次ルーティン(打席数の設計)

成約率10%前提で逆算:

| 目標 | 必要提案数 |
|---|---|
| 月1件受注(Phase 0) | 月10提案 ≒ **週2〜3提案** |
| 月2件受注(Phase 1〜) | 月20提案 ≒ **週5提案** |

ルーティン(週合計 約2時間):
- **平日夜(10分×3回)**: 新着通知をチェック → 狙い目シグナルに合う案件をブックマーク
- **提案作成(20分×週2〜5本)**: 下の型に沿ってClaudeでドラフト → 自分の言葉に調整して送信
- 提案ログ(§6)に記録

## 4. 提案文の型(3パターン)

共通原則([freelance.md §5](freelance.md)のテンプレがベース): クライアントが見ているのは実績の量ではなく**「この人に安心して任せられるか」**([出典](https://www.shiomi.blog/claudeworks-saiyou-oubobun/))。募集文から「発注者の本当の悩み」を読み取り、自分を選ぶ理由と期待以上の付加価値を添える([出典](https://freelance-start.com/articles/1237))。

### 型A: 要件が明確な案件(基本形)

1. 課題の言い換え(募集文を自分の言葉で要約 — コピペ提案でない証明)
2. 実現方法を非エンジニア向けに2行で
3. 納期・見積り・調整回数(「初回版◯日→確認→調整2回まで込み」)
4. ポートフォリオリンク

### 型B: 要件が曖昧な案件(ヒアリング提案)

「〜という理解で合っていますか?もし△△の場合は□□という方法もあります」と**選択肢を提示して質問で終える**。返信をもらうこと自体が目的(会話が始まれば受注率が跳ね上がる)。曖昧なまま金額は確定させない(「詳細確認後に正式なお見積りをご提示します。想定レンジは◯〜◯円です」)。

### 型C: デモ付き提案(必殺技・勝負案件用)

要件が具体的で単価が良い案件には、**提案前にClaudeで動くプロトタイプを作り、スクショまたはGIFを添付する**。

> 「ご要望の動作イメージを簡単なサンプルで作成してみました(添付)。ご発注いただければ、実データの形式に合わせて◯日で完成させます」

- 制作コスト: Claude活用で30〜60分
- 実績ゼロを一撃で無効化する(動くものを見せる提案者はほぼいない)
- 週1本まで(コストがかかるため、単価15,000円以上×要件明確の案件に限定)

## 5. 価格戦略(評価ドリブン)

CWのGAS/スプシ案件相場は数千円〜数万円、小規模自動化のボリュームゾーンは1〜3万円、大きめで3〜8万円([相場情報](https://note.com/zero_sta1/n/n337523f58e71)、[報酬相場](https://remogu.jp/c/%E3%80%90gas%E3%80%91%E6%A5%AD%E5%8B%99%E5%A7%94%E8%A8%97%E3%81%AE%E5%A0%B1%E9%85%AC%E7%9B%B8%E5%A0%B4%E3%81%A8%E3%82%B9%E3%82%AD%E3%83%AB%E3%83%AD%E3%83%BC%E3%83%89%E3%83%9E%E3%83%83%E3%83%97/))。

| 段階 | 価格方針 | 狙い |
|---|---|---|
| 評価0〜2件 | 相場の下限(5,000〜10,000円の小型案件中心) | **最初の評価の獲得が最優先**。実績ゼロが最も受注しづらい([出典](https://jp-now.net/column-crowdsourcing-tips/)) |
| 評価3〜9件 | 相場中央値([freelance.md §7](freelance.md)単価表) | 型Cデモ提案で15,000円以上を狙い始める |
| 評価10件〜 | 中央値以上+継続契約の提案 | 納品時に「月◯円で保守・改修対応も可能です」を定型で添える |

**受注済み案件からの派生が最効率**: 納品時に「他にも自動化できそうな作業があればお気軽に」と一言添える。既存クライアントの追加依頼は提案競争がゼロ。

## 6. KPIファネル(月次レビューに記録)

```
提案数 → 返信率 → 受注率 → 平均単価 → 時給換算
```

| 指標 | 健全ライン | 下回ったときの対処 |
|---|---|---|
| 返信率 | 20%以上 | 提案文の問題 → 型を見直す・冒頭の課題言い換えを強化 |
| 受注率(提案比) | 10%以上 | 案件選定の問題 → 提案数の多い案件を避ける・単価を一段下げる |
| 平均単価 | 段階表どおり | 評価数が足りているなら型Cの比率を上げる |

[progress/_template.md](progress/_template.md)の案件ログと合わせて記録する。

## 7. CW特有の注意事項

- **仮払い(エスクロー)確認前に作業を開始しない**(未払いトラブルの大半はこれ)
- 直接取引への誘導(LINE・メールでのやり取り+直接支払い)は**規約違反**。アカウント停止リスクがあるので即断る
- 契約途中の追加要望は「調整◯回まで込み」の範囲外なら、CW上で追加契約を結んでから対応
- 検収後の評価依頼は必ず送る(評価コメントを書いてもらえるかが次の受注率に効く)
- 悪質クライアントのシグナル: 評価4.5未満・過去のワーカー評価コメントに「連絡が取れない」がある・仮払いを渋る → 見送る
