## 1. 目的とポジショニング

個人事業主・小規模事業者の「お金の期日のうっかり」を潰すGASテンプレ。売掛（もらう側）と買掛（払う側）の期日を **1シートで両面管理** し、LINE/Slackで **能動プッシュ通知** する。

**差別化（BOOTH競合調査で確認済みの空白）:**
1. **買掛（支払う側）の期日前アラートはBOOTHに存在しない**（「支払 期日 通知」検索は業務系ゼロ）。
2. 既存の入金管理はNotion/Excelの **受動フラグ表示**止まり（開かないと気づけない）。本製品はLINE/Slack能動プッシュ。
3. **売掛×買掛を1枚で両面**管理する商品が無い（既存は入金＝片側だけ）。

**対抗馬:** コアリンク「フリーランス収支・案件管理」¥2,480（確定申告集計込みで重い）。
本製品は「期日を1件も逃さない一点特化・軽い・導入が速い」で差別化。

**価格:** ¥1,480（1本目¥1,280の少し上）。

## 2. スコープ

### やること
- 売掛/買掛の期日監視
- 買掛：期日の N日前に「支払予告」通知
- 売掛：期日超過かつ未入金で「督促」通知
- LINE / Slack 通知（1本目と同方式）
- 「済」チェックで通知停止
- 送信ログ・重複送信防止

### やらないこと（YAGNI / 別製品領域）
- 銀行API連携・入金自動検知（済は手動チェック）
- 請求書PDF生成（別領域）
- 消込の自動マッチング、複数通貨

## 3. アーキテクチャ

1本目（reminder-mailer）の構成を踏襲。純粋ロジックを `core.js` に閉じ込め、GAS依存を `main.js` に分離。**新フォルダ `tools/dual-due-alert/` に自己完結の別製品として構築**（購入者に渡すのは単体で動くテンプレ）。

```
tools/dual-due-alert/
  core.js        # 純粋ロジック（Nodeでテスト可能）
  main.js        # GASグルー（Sheets/Trigger/通知）
  core.test.js   # 単体テスト
  README.md / 手順書.md
  booth-kit/     # 出品文・カバー画像・特商法・チェックリスト・購入者DL
```

`core.js` は1本目の `selectDue` を流用・拡張。`selectDue` は既に offsets（期日N日前）＋ overdueAlert（超過）両方に対応しているため、追加は「種別（売掛/買掛）」の保持と「済」による除外、種別に応じたメッセージ分岐のみ。

## 4. データモデル

### シート「取引一覧」（DATA_SHEET）
| 列 | 見出し | 型 | 用途 |
|---|---|---|---|
| A | 種別 | 売掛/買掛（ドロップダウン） | 通知セマンティクスとメッセージを分岐 |
| B | 取引先 | 文字列 | メッセージ差し込み {取引先} |
| C | 金額 | 数値 | メッセージ差し込み {金額} |
| D | 期日 | 日付 | 監視対象 |
| E | 済 | チェックボックス | ☑で以後通知しない |
| F | メモ | 文字列 | 任意 |
| G | 送信状態 | 文字列（内部用） | 重複送信防止（1本目と同方式） |
| H | 最終送信日時 | 文字列（内部用） | |
| I | 有効 | チェックボックス | 行のON/OFF |

### シート「設定」（CONFIG_SHEET）
1本目の設定に準拠：
- 通知先(slack/line)、Slack Webhook URL、LINEアクセストークン、LINE userId
- 送信オフセット（買掛の期日前日数。既定 `7,3,1,0`）
- 督促開始（売掛が期日を過ぎてから通知。ON/OFF、既定 ON）
- 1回の送信上限、実行時刻(0-23)、差出人名
- メッセージテンプレ：`買掛テンプレ` / `売掛テンプレ`（種別ごと）

### シート「送信ログ」（LOG_SHEET）
`日時 / 対象行 / 種別 / オフセット or 督促 / 通知先 / 結果`

## 5. 通知ロジック

各行を `selectDue` で評価（today基準）。除外条件：`有効=FALSE`、`済=TRUE`、期日不正。

- **買掛**：`期日までの残り日数` が 送信オフセットに一致 → ラベル（例 `-3`）。既送信でなければ通知。
  - 文面例：`【支払】{取引先} への {金額}円 の支払期日は {期日}（残り{残り日数}日）です`
- **売掛**：`期日 < today`（超過）かつ督促ON → ラベル `超過`。既送信でなければ通知。
  - 文面例：`【入金遅延】{取引先} からの {金額}円 が {期日}を過ぎています。督促を検討してください`
- 「済」☑で全ラベル停止。同一ラベルは送信状態で重複防止。

差し込み変数：`{取引先} {金額} {期日} {残り日数}`。

## 7. テスト計画（TDD）

純粋ロジックを `core.js` に閉じ込め Node で単体テスト（1本目 `core.test.js` 踏襲）：
- `selectDue`：
  - 買掛＝期日N日前のみ拾う（オフセット一致）
  - 売掛＝超過のみ拾う（期日前は拾わない）
  - 「済」で除外
  - 送信状態で重複除外
  - 有効=FALSEで除外
  - 境界（当日=0）
- `renderTemplate`：{取引先}{金額}{期日}{残り日数} の差し込み
- メッセージ分岐：種別ごとに正しい文面（支払予告 vs 督促）

GAS依存部（notify/trigger/Sheet I/O）は1本目で実証済みのため、テスト送信メニューで手動確認。
