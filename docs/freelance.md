# 開発代行の手順書(柱1・主軸)

GAS・スプレッドシート自動化を中心とした開発代行で、月1〜2件 × 単価5,000〜30,000円 = 月1〜3万円を稼ぐための実務手順。

## 1. なぜGAS・スプレッドシート自動化か

- クラウドワークスで関連案件が**常時700〜1,000件**、ボリュームゾーンは**5,000〜30,000円**([出典](https://note.com/thesaurus1/n/n73dc9d25fe10))
- 発注側は非エンジニアの中小企業が多く、要件が小さく定型的 → Claudeでの実装と相性が良い
- Googleアカウントだけで動くため納品が軽い(環境構築・サーバー不要)
- 週5〜10時間で月3〜5万円の事例が多数([GAS副業ガイド](https://techgym.jp/fukugyo/gas/))

## 2. プラットフォーム戦略

| プラットフォーム | 使い方 | 手数料 | 特徴 |
|---|---|---|---|
| クラウドワークス | **能動応募**(メイン) | 5〜20%(20万以下は20%) | 案件数最多。GAS/スプシ案件の主戦場 |
| ランサーズ | 能動応募(サブ) | 一律16.5% | CWと二刀流で応募母数を増やす |
| ココナラ | **出品して待ち受け** | 22% | 「スプシ自動化します」等の定型メニューを出品。Phase 2で拡充 |

方針: Phase 0〜1はCW/ランサーズへの応募で実績と評価を作り、並行してココナラに出品を置いておく(待ちの受注は評価が貯まると増える)。

## 3. プロフィール・ポートフォリオ整備(Phase 0)

プロフィールに書くこと:
- 提供できること(GAS/スプシ自動化・データ集計・定型業務の自動化)を**発注者の言葉**で書く(「業務効率化」「毎日の手作業をなくす」等。技術用語を並べない)
- 対応可能時間帯(平日夜・週末)と返信スピードの目安を明記(副業でも返信が早いと信頼される)
- 公開ツール([apps.md](apps.md)で作るもの)へのリンク = 動くポートフォリオ

ポートフォリオの初期セット(受注ゼロでも作れる実績):
1. マイクロツール第1号(柱2と兼用)
2. サンプルGAS 2本をデモ動画/スクショ付きで紹介(例: スプシ→Gmail自動送信、フォーム回答の自動集計)

## 4. 案件選定チェックリスト

応募して良い案件(すべて満たす):
- [ ] スコープが1〜2文で説明できる(「AをしたらBされるようにしたい」)
- [ ] 完成条件が明確、または初回メッセージで明確化できそう
- [ ] 納期に1週間以上の余裕がある
- [ ] 発注者の評価・本人確認がある
- [ ] 時給換算で2,000円以上見込める(実稼働2〜4時間なら単価8,000円〜が目安)

避ける案件(ひとつでも該当したら見送る):
- 「詳細は契約後に」など要件を隠している
- 相場から極端に安い大量作業(例: 1万円で10機能)
- 継続前提の常駐型・週次MTG必須(週10時間制約に反する)
- 他人のアカウント操作・規約違反系(スクレイピング先の利用規約違反、SNS自動操作など)
- **同時進行が既に2件ある場合は新規応募しない**(納期事故防止)

## 5. 提案文テンプレート

> はじめまして。スプレッドシート・GASを使った業務自動化を専門にしております。
>
> ご依頼の「◯◯」について、以下の流れで実現できます:
> 1. △△(発注者の課題を自分の言葉で言い換える — コピペ提案でない証明)
> 2. □□(実装方針を非エンジニア向けに1〜2行で)
>
> 類似の制作例: (ポートフォリオURL / スクショ)
>
> 納期: ご発注から◯日以内に初回版をお渡しし、動作確認いただいた上で調整いたします(調整◯回まで込み)。
> お見積り: ◯◯円
>
> ご不明点があればお気軽にご相談ください。

ポイント:
- **課題の言い換え**が最重要。テンプレ一斉送信と差別化される
- 「初回版→確認→調整」の流れを先に示すと発注側の不安が減る
- 調整回数を先に区切る(無限修正の防止)

## 6. 受注〜納品ワークフロー(Claude活用)

| ステップ | 担当 | 内容 |
|---|---|---|
| 1. 要件確認 | 人間 | 完成条件・入出力・締切を確認し、箇条書きで合意を取る |
| 2. 実装 | **Claude** | 要件をそのまま渡して実装。エッジケース・エラー処理も指示 |
| 3. 動作確認 | 人間 | 実データ相当のテストケースで必ず自分で動かす(**ここは省略しない**) |
| 4. 納品物作成 | **Claude** | 導入手順書(スクショ付き)・使い方説明を生成 |
| 5. 納品・調整 | 人間 | 初回版を渡し、フィードバックをClaudeに渡して修正 |
| 6. クローズ | 人間 | 検収依頼・評価依頼。案件内容を[progress](progress/)に記録 |

1件あたりの想定実稼働: **2〜4時間**(うちClaude作業を除く人間の時間は1〜2時間)。

## 7. 単価表(自分用の見積もり基準)

| 案件タイプ | 目安単価 | 実稼働目安 |
|---|---|---|
| スプシ関数・小規模GAS(1機能) | 5,000〜10,000円 | 1〜2h |
| GAS自動化(複数機能・外部連携なし) | 10,000〜20,000円 | 2〜4h |
| 外部API連携(LINE/Slack/freee等)込み | 20,000〜40,000円 | 4〜8h |
| 保守・改修(リピート) | 5,000円〜/回 | 〜1h |

Phase 0〜1は評価獲得優先で下限寄り、評価10件を超えたら中央値以上に引き上げる。

## 8. トラブル回避

- 金銭のやり取りは必ずプラットフォームを通す(直接取引の誘いは規約違反かつ未払いリスク)
- 仕様追加は「調整◯回まで込み」の範囲を超えたら追加見積りを提示する(無償対応しない)
- 納期が危うくなったら**遅れる前に**連絡する(事故のほとんどは無連絡遅延)
- 納品コードには自分の秘密情報(APIキー等)を絶対に含めない。発注者側で発行してもらう
- 請け負わない領域を決めておく: 法的にグレーなスクレイピング、他人アカウントの自動操作、投資の自動売買の運用責任
